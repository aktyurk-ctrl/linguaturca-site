# Перенос living school в production

Утверждённая главная перенесена в Next.js 16 / React 19 в ветке `codex/living-school-production`. Эталон — `docs/design-concept/living-school/` из коммита `6f6228b36c38804817c5dbbd3b39cd014e1693c0`. Сам эталон не изменён. Миграция Next.js, зависимости, API и содержимое внутренних страниц сохранены. Push и deploy не выполнялись.

## Что перенесено

Header, hero, позиционирование, два формата, методика, преподаватели, организация занятий, тарифы, языковой блок с hocam, отзывы, FAQ, заявка и footer. Сохранены содержание последнего content pass, фотографии, Manrope/Onest, бирюзовые акценты, размеры, отступы, поверхности и responsive-правила.

Порядок взят из самого утверждённого HTML: преподаватели перед организацией занятий. Это соответствует визуальному эталону; в нумерованном перечне задания эти два блока были перечислены наоборот.

`app/page.tsx` теперь собирается из серверных секций в `src/components/living-school/`. Клиентский код обслуживает только меню, выбор тарифа, раскрытие языковой заметки, просмотр исходных отзывов и форму. FAQ использует нативные `details/summary`. Повторяющиеся данные вынесены в `src/data/living-school.ts`.

CSS из эталона сведён в локальный `LivingSchool.module.css`: переменные бренда, типографика, размеры, стили секций и адаптивные правила. Manrope и Onest подключены локально через `next/font/local`, с лицензиями OFL. Существующие изображения используются через `next/image`; оригиналы отзывов показываются без преобразования.

## Заменённые и неиспользуемые компоненты

Заменены production `app/page.tsx`, shared `Header.tsx` и `Footer.tsx`. Старые глобальные правила перенесены в `.legacy-content` и оставлены только для статей, документов и существующего cookie notice, чтобы они не изменяли новый дизайн. Содержимое страниц статей, оферты и политики не переписано.

Старая главная больше не подключает `AboutSection`, `HowWeTeachSection`, `CourseMiniGroupSection`, старые `PricingSection` и `IndividualPricing`, `FreeConsultationSection`, `ScheduleSection`, `ReviewsCarousel`, `FinalCTASection`, `HeroForm`, `HeroFormButton`. Глобальные `LeadModal` и `LeadModalProvider` больше не монтируются. Их исходники сохранены для отдельной уборки legacy; старые карусели и анимации не возвращены на главную.

## Форма и Airtable

`LeadForm.tsx` сохраняет выбранные формат и тариф, переводит фокус к имени, валидирует поля и показывает loading/error/success. Email необязателен. При ошибке введённые поля сохраняются. Повторная отправка блокируется на время запроса.

Транспорт `src/lib/lead-request.ts` вызывает прежний `POST /api/airtable`. Активный обработчик `app/api/airtable/route.ts` не менялся и по-прежнему требует `AIRTABLE_API_KEY`, `AIRTABLE_BASE_ID`, `AIRTABLE_TABLE_NAME`. Выбранный тариф передаётся в существующем текстовом `source` («Секция сайта»), например `living-school · Комфорт`; новых полей Airtable нет. Неактивный дубликат `src/app/api/airtable/route.ts` и legacy-формы также оставлены без изменений.

Реальные заявки при проверке не отправлялись. Успех, отказ сервера, некорректный ответ и сетевой сбой проверены на подменённом транспорте. Сквозная доставка в Airtable намеренно не проверялась. Backend и будущая миграция CRM остаются отдельной задачей.

## Responsive и визуальная сверка

Проверены 320, 390, 768, 1024 и 1440 px в браузере. Нет горизонтального переполнения или незагруженных видимых изображений. Высоты и начальные координаты всех 11 основных секций совпадают с эталоном на каждой ширине. Кадрирование, переносы и типографика просмотрены визуально; дополнительно сравнивались скриншоты и DOM-геометрия. Это проверка одного браузерного движка, а не полная матрица Safari/Firefox/Android.

Известные расхождения:

1. Демо-подпись формы заменена на «Заявка на бесплатную консультацию», демонстрационные переключатели состояния отсутствуют. Успех/ошибка зависят от настоящего ответа существующего API.
2. В footer удалены служебные ссылки «О макете» и «Скриншоты». Footer короче на 54,59 px; остальные секции не сдвинуты.
3. Изображения оптимизируются Next.js, поэтому пиксели фотографий могут немного отличаться при том же кадрировании.
4. «Источник разбора» ведёт непосредственно на источник из content audit вместо служебной страницы заметок. Статьи используют внутренние маршруты вместо локальных адресов прототипа.
5. Сохранено production-уведомление о cookies; для сравнительных скриншотов оно закрыто.

Отдельно исправлены два технических конфликта переноса: специфичность scoped CSS и отрицательный z-index подложки культурного блока. Они не оставлены как визуальные упрощения.
